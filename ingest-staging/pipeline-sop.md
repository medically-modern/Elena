# Patient Pipeline SOP — v1.1 (updated 2026-06-26: Medical Necessity stage rules deferred to sop:medical-necessity. Base v1.0 2026-06-11, confirmed by Josh)

PIPELINE OVERVIEW - Medically Modern's patient pipeline runs through the Command Center (medically-modern.github.io/command-center-test) backed by Monday boards. Stages in order: 1. Profile Checklist / Intake (Profile Send Off board) -> 2. Medical Necessity with sub-stages Evaluate, Send Request, Confirm Receipt, Chase Clinicals (Medical Evaluation board) -> 3. Insurance & Benefits with sub-stages Benefits, Submit Auth, Auth Outstanding (Insurance board) -> 4. Welcome Call then Final Profile Confirmation (Welcome Call board) -> 5. Order, fulfillment and claims (Order/Claims boards) -> ongoing Subscription (Subscription board). Pipeline oversight and patient velocity is managed by Janelle.

STAGE ROLE ASSIGNMENTS - from the Command Center role assignments page: Profile Checklist: Corey, Janelle. Evaluate / Send Request / Confirm Receipt / Chase Clinicals (Medical Necessity sub-stages): Masheke, Brandon, Corey, Janelle. Benefits: Samantha, Brandon, Corey, Janelle. Submit Auth and Auth Outstanding: Brandon, Corey, Samantha. Welcome Call: Corey, Janelle. Final Profile Confirmation: Brandon, Janelle, Corey. Subscription: Josh, Janelle. Update Clinicals: Masheke. Auth Denied: Corey. Patient Questions: Janelle, Josh.

INTAKE / PROFILE CHECKLIST EXIT CRITERIA - A patient cannot be advanced from Profile Checklist to Medical Necessity until every required field is filled (the Command Center blocks the "Advance to MN" button otherwise). Required: Name, DOB, Phone, Gender, Primary Insurance, Serving, Cross-Sell Status, IP Coverage Path (insulin pump coverage path), CGM Coverage Path, Pump Type, and CGM Type. Pump Type and CGM Type are always required - "Not Serving" is a valid selection. Doctor Fax is additionally required when the clinicals method is Fax. Intake channels include Parachute referrals (automated), CareCentrix referrals (manual add from Service Registration/CN/DWO PDFs), direct-to-consumer text leads, and partnership intake.

REFERRAL SOURCE AND REFERRAL TYPE (two separate columns, set at intake in the REFERRAL DETAILS section) - Referral SOURCE is the specific partner who sent us the patient. Its active values are: Patient, Tandem, Beta Bionics, CareCentrix, Doctor, Wellstart, Solace Advocates, SNJ, District Endochrine. Referral TYPE is the category that source falls into: Manufacturer, Payor, Patient, Doctor, Advocacy Group. SNJ is a referral SOURCE - a named partner, and by volume our largest one. It is not an insurance carrier, a state, or a sales territory. Both columns exist on the Profile, Medical Evaluation, Insurance and Welcome Call boards; the Subscription board carries its own separate Referral Source column. To answer "how many <partner> patients", filter or count on Referral Source, never on insurance.

ACTIVE PIPELINE - THE DEFINITION - "Active pipeline" means the live working stages only: Intake (Profile board), Medical Necessity (Medical Evaluation board), Benefits, Submit Auth, Auth Outstanding (Insurance board), Welcome Call and Final Profile Confirmation (Welcome Call board). The Completed, Stuck, Escalation, Archived DTCs, Already In System and New Form partial-lead groups are NOT active pipeline. Any pipeline count must say which definition it used.

MEDICAL NECESSITY STAGE RULES - Sub-stages in order: Evaluate -> Send Request -> Confirm Receipt -> Chase Clinicals. The authoritative rules for this stage live in the Medical Necessity Stage SOP (source sop:medical-necessity); refer to it for channel routing (fax vs Parachute), the fact that Confirm Receipt is fax-only (Parachute requests skip it and go straight to Chase Clinicals), the per-bucket attempt cadences, and escalation handling. In brief: 3 exhausted attempts on Confirm Receipt, or on either Chase Clinicals bucket, route the patient to Manager Review, owned by Janelle. Masheke owns clinicals gathering and the Update Clinicals queue.

INSURANCE AND BENEFITS STAGE RULES - Owner Samantha with Brandon oversight. Sub-stages: Benefits (run Stedi eligibility check, classify primary insurance, check DME benefits, network status, and same-or-similar) -> Submit Auth -> Auth Outstanding -> Complete. Auth requirements per product come from the payer rules tables. Per-product auth results and auth IDs are tracked on the Insurance board. Stedi eligibility checks ARE required for CareCentrix referrals, same as every other referral source (confirmed by Josh 2026-06-11; historically some CareCentrix Horizon BCBS patients were missed).

SEND-BACK-TO-BENEFITS RULE - Team members CANNOT send a patient from a later stage back to Benefits themselves; it is not supported in the Command Center UI. It requires Josh's help (engineering action). If a patient needs to go back to Benefits (payer change, missed auth), flag Josh.

AUTH DENIED - The Auth Denied group on the Insurance board is owned by Corey. A formal appeal workflow has NOT been created yet (as of 2026-06-11). Denied-auth patients sit in Auth Denied until handled case by case.

WELCOME CALL AND FINAL PROFILE CONFIRMATION - Welcome Call owners: Corey and Janelle. Confirm products and variants, quantities, address, doctor, and patient expectations; advance only when info checks out. Final Profile Confirmation owners: Brandon, Janelle, Corey - full profile review where auth information is displayed so the team can verify auth coverage matches what ships.

PRODUCT CHANGES - Product changes can be made through the reorder link (the patient-facing tokenized reorder form). This is the supported path for changing products rather than manual board edits.

SUBSCRIPTION / RESUPPLY TRACK - Subscription board owners: Josh and Janelle. Groups: Subscriptions and Not Active Patients. Resupply cadence is driven by the 20-day reorder text system (patient confirms via tokenized link, where product changes are also supported). Monthly batch eligibility re-checks run via the batch flow. Financial estimates (sensors/supplies revenue, cost, GP) are computed per fill.

STAGE SLA - The goal is under 3 days per stage (the boards track Days Since Stage Started in buckets: 0-2, 3-5, 6-8, 9-12, 13-15, 16-20, 21-29, 30+ days since intake). IMPORTANT: before judging a delayed patient, always review the notes on the patient's profile to get context - a patient may be legitimately waiting on a doctor, payer, or the patient themselves.

PATIENT QUESTIONS QUEUE - Inbound patient questions are handled by Janelle and Josh via the Patient Questions page in the Command Center.

OPEN ITEMS (not yet defined as of 2026-06-11) - Shipping ownership and cutoff times: not documented yet. Whether subscription patients ever require intake completion: not documented yet. Auth Denied appeal workflow: not created yet.
